Phase **P5.9 Persistent Trust Anchors & Verification** productionizes the P5.8 Trust Anchor abstraction by introducing relational PostgreSQL persistence, SQLAlchemy 2.x ORM mappings (`TrustAnchorModel`), Alembic schema migration `002_add_p59_trust_anchors`, atomic transaction management via `session_scope`, and the `PostgresTrustAnchorRepository` conforming strictly to the `TrustAnchorRepository` protocol.

## 2. Repository Implementation & Semantics

### `PostgresTrustAnchorRepository`
Conforms to `TrustAnchorRepository` Protocol:
1. **`save(anchor: TrustAnchor) -> TrustAnchor`**:
   - Atomic transaction via `session_scope`.
   - **Idempotency**: If `device_id` already exists with identical `passport_fingerprint`, returns the existing record cleanly without raising exceptions or creating duplicates.
   - **Conflict Rejection**: If `device_id` already exists with a different `passport_fingerprint`, raises `AnchorConflictError` (HTTP 409 Conflict), preventing silent overwrite.
2. **`get_by_device_id(device_id: str) -> TrustAnchor | None`**:
   - Queries `TrustAnchorModel` by `device_id` and maps to immutable `TrustAnchor` domain dataclass.
3. **`exists(device_id: str) -> bool`**:
   - Fast SQL count query.
4. **`count() -> int`**:
   - Aggregates total anchored records.
5. **`clear() -> None`**:
   - Drops all rows in `trust_anchors` table (test utility).
